### Naming

A leading underscore means **module-private**. A helper another module imports
is package API and must not carry one, or the convention says nothing.

**No two modules may define the same name.** The import tooling keeps one
entry per symbol, so a duplicate makes it inject a cross-module import that
silently shadows the local definition. That is how `records._scalar` came to
be overridden by `formats._scalar`, quietly disabling nested media expansion.
Name functions for what they do: `_cell_value` flattens a value for a tabular
cell, `_jsonable` preserves structure.

A constant referenced only by its own test is ceremony, not a source of truth;
assert the literal in the test instead.

**Name nothing like a secret that is not one.** CodeQL's
`py/clear-text-logging-sensitive-data`, like other scanners, decides what is
sensitive from names: a variable, attribute, parameter, or function matching
`secret` or `password` (`pass(wd|word|code|phrase)`), or a lookup by such a
string, is a secret to it, and so is everything computed from one, until it
reaches a log call or `print` and is reported as a leak. A name containing
`file`, `path`, or `url` is exempt. So the secrets file's path is
`Paths.secrets_file`, never `Paths.secrets`; the count of forgotten saved
passwords comes from `forget_logins`, not `forget_passwords`; the
`--save-password` flag's dest is `remember_login`; the migration's counts are
variables of their own rather than `moved["passwords"]`; and the tuples of
option names are `STORE_CHOICES`, `_KEYRING_OPTIONS`, and
`_SCRUBBED_OPTIONS`. The converse matters as much: what does hold a password
or a token keeps a name saying so (`password`, `saved_password`, `secrets`),
so that a real leak is still reported. The public option names
`secret_store` and `secrets_file` are API and do not change.

### Character set

Source, completions, man page, and build files are **plain ASCII**. Write `-`
not an em dash, `->` not an arrow, `>=` not the inequality sign, `...` not an
ellipsis, a straight `'` not a curly quote. This applies to comments,
docstrings, and user-facing message strings alike: a warning printed to a
terminal has no business containing an em dash.

Two deliberate exceptions, both about output rather than prose: `console.py`
holds the box-drawing glyphs as `\uXXXX` escapes, so the file itself stays
ASCII while the tables still draw; and the markdown docs keep literal box
characters where they reproduce program output or draw a `tree`-style listing.

The imports form no cycle: `config` reads the file and knows nothing of
secrets; `secret_store` uses `config` for its two options; `tokens` uses
`secret_store`; `connection` uses `config` and `tokens`; `migrate` uses
`secret_store` and `constants`, and runs from `cli.main` before any command,
not from `load_config`, which would close the loop.

### Command module contract

Every module in `commands/` exposes exactly three names:

- `register(sub, parents)` adds its subparsers, passing `parents=parents` on
  every `add_parser` call so each inherits the global flags.
- `COMMANDS` maps command name to handler.
- `REQUIRES_PLEX` is the subset needing a server; `auth` has an empty
  frozenset because `login` and the two `write-*-example` commands run
  before a token exists, `logout` must work once the server no longer
  accepts one, and `set-pin` only touches the secret store.

`commands/__init__.py` holds a `MODULES` tuple, `register_all(sub, parents)`,
`build_registry()`, and `GROUPS`, which is what `--help` lists the commands
from (see COMMAND NAMES AND HELP). Adding a command means adding a module,
listing it, and naming the command in one group; `cli.py` never changes.

## PLATFORM DEFAULTS

`constants.default_paths(is_windows, env)` returns a `Paths` tuple: the
config file, the cache directory, the secrets fallback file, and plexdo 1.x's
INI file and default token path, for the migration. Take the flag and
environment as arguments rather than reading `os.name` inside, so both
branches are testable from either platform: forcing `os.name` on Linux makes
`pathlib` fail to build a `WindowsPath`.

| | config | cache | secrets fallback |
| --- | --- | --- | --- |
| Linux, macOS, BSD | `$XDG_CONFIG_HOME/plexdo/config.yaml` | `$XDG_CACHE_HOME/plexdo` | `$XDG_STATE_HOME/plexdo/secrets.json` |
| Windows | `%LOCALAPPDATA%\PlexDo\config.yaml` | `%LOCALAPPDATA%\PlexDo\Cache` | `%LOCALAPPDATA%\PlexDo\secrets.json` |

The XDG variables default to `~/.config`, `~/.cache`, and `~/.local/state`,
and one set to a relative path is ignored, as the XDG Base Directory
Specification requires. The secrets fallback lives in the state directory
because it must survive a reboot, which `XDG_RUNTIME_DIR`, 1.x's choice for
its token, does not. `APPDATA` is the Windows fallback when `LOCALAPPDATA`
is unset. All four shell completions must resolve the same cache location,
or completion silently stops working under Git Bash.

## CONFIGURATION

The configuration file is YAML and holds **no secrets**:

```yaml
---
plex:
  url: "http://localhost:32400"
  # username: "you@example.com"
  # cache_dir: "~/.cache/plexdo"
  # secret_store: "auto"
  # secrets_file: "~/.local/state/plexdo/secrets.json"
users:
  99:
    username: "bob@example.com"
```

- `config.parse_config` reads it with `yaml.safe_load` and checks it into
  `{"plex": {option: text}, "users": {"<id>": {option: text}}}`, every value
  a stripped string and every user id a string of digits. An unknown section
  or option is warned about by name and ignored; `password`, `pin`, `token`,
  or `token_path` is warned about as a secret that belongs in the keyring
  and ignored, so a value carried over from 1.x never reaches use. Malformed
  YAML, a list where a value belongs, a user id that is not numeric, and a
  `secret_store` other than `auto`, `keyring`, or `file` are each a
  `sys.exit` saying what is wrong. A missing `url` is an error where a
  server is needed (`connection.server_url`), not on loading, so
  `logout` and `set-pin` work without one.
- Expand environment variables in `url`, `cache_dir`, and `secrets_file`
  with `os.path.expandvars`, which follows the platform (`%VAR%` on Windows,
  `$VAR` everywhere). An unset name is left literal, which would surface
  much later as a confusing "no such file", so warn about any name still
  present after expansion, in whichever spelling the platform accepts.
- `cached_config()` is memoised with `lru_cache(maxsize=1)`: the per-user
  paths read `users` entries once per user in a loop, and re-reading would
  re-emit every warning each time.
- `constants.config_text(url, username, cache_dir, users)` writes the file
  with **every option explained** - its meaning, valid values, and default,
  the default on a line of its own so a long path is never split - as
  comment paragraphs filled to 76 columns by `textwrap`. Values are quoted
  with `json.dumps`, valid YAML for any text. `CONFIG_EXAMPLE` is
  `config_text()`, written by `write-config-example`; the 1.x migration
  writes it with the values it found, so a migrated file is as documented
  as a fresh one. It opens with `---` and passes yamllint.

## SECRETS AND MULTI-USER ACCESS

Tokens, passwords, and Plex Home PINs are kept by `secret_store.py` in the
system keyring through the `keyring` package: the Secret Service on Linux
and BSD, the Keychain on macOS, and Credential Manager on Windows. Each kind
is **one entry** under service `plexdo`, holding a JSON object: `tokens`
(username -> token), `passwords` (username -> password), `pins` (user id ->
PIN). One entry per kind, not per secret, because a keyring cannot list what
it holds and `logout` must find every token. Saving a kind with nothing left
removes its entry.

- `plex: secret_store` chooses the store. `auto`, the default, uses the
  keyring when `keyring.get_keyring()` is a real one - not `fail.Keyring`,
  nor a `ChainerBackend` with no backends - and otherwise the file, with a
  WARNING that it is unencrypted and how to silence it; `keyring` insists,
  and exits explaining when there is none; `file` never asks the keyring,
  for a machine where it is locked when plexdo runs, as under cron.
- The file, `plex: secrets_file` or the platform default, is one JSON object
  of kind -> object, created with `os.open(..., 0o600)` so it is never
  readable by anyone else even for a moment, replaced atomically, and
  deleted with its last secret. `check_file_permissions` warns when it is
  readable by group or other, at WARNING level so it shows without
  `--verbose` and on stderr so it never contaminates `--json`; it returns
  early on Windows, which has no POSIX mode bits.
- A keyring failure, locked or its prompt dismissed, is a `sys.exit` naming
  `secret_store: file` as the way out.
- `secret_store.backend()` is chosen once per run and works before the
  config exists, with the defaults, since the migration saves secrets
  before writing the file.
- **With `secret_store: file` set outright, sessions are kept apart from
  passwords.** `SESSION_KINDS` is `("tokens",)`; `session_backend()` is the
  store for those kinds and `backend()` the store for the rest, and
  `load`, `save`, and `describe(kind)` pick between them. Under `auto` and
  `keyring` the two are the same store, a file `auto` fell back to
  included. Under `file` the secrets file holds `passwords` and `pins`
  alone, and the tokens go in a `SessionStore`, a `FileStore` at
  `constants.DEFAULT_SESSION_FILE`: `$XDG_RUNTIME_DIR/plexdo/session.json`
  when that variable is an absolute path, else `plexdo-UID/session.json`
  under `tempfile.gettempdir()`, which honours `TMPDIR`, `TEMP`, and `TMP`
  (`PlexDo/session.json` there on Windows). `session_file(is_windows, env,
  tmpdir, uid)` takes all four as arguments so every case is testable.
  The reasoning: that setting is for a machine with no keyring to unlock,
  where the secrets file is all that guards a saved password, and a token,
  which changes with every login and which plex.tv can reissue, does not
  belong beside it or need to outlive a reboot.
- The temporary directory is writable by other accounts, so the session
  directory is created with mode 0700 and then checked with `lstat`: it
  must be a real directory, not a link, owned by the user. One of the
  user's own that is open to group or other is tightened. Otherwise
  writing is a `sys.exit` and nothing is written, and a session file
  found there is ignored with a warning rather than believed. Windows has
  neither check; its temporary directory is inside the user's profile.
- The first time the session store is opened, a `tokens` entry still in
  the secrets file, where it was kept before, is moved to the session
  file, a token already there winning, with a warning saying so. An
  upgrade must not sign anyone out.
- `login` prints one note on **stderr**, in every format, when the two
  stores differ: where sessions are kept, that they are apart from the
  passwords and PINs, and that a session lasts until that file is cleared,
  as at a reboot, when `plexdo login` is needed again.

`tokens.py` is the only module that knows the three kinds.

- `ADMIN_KEY` is `"@admin"`, for a token saved with no username known; `@`
  cannot occur in a Plex username. `admin_token(username)` resolves in
  order: the configured username, the reserved key, then a store holding
  exactly one entry.
- A password is saved only by `login --save-password`, filed by username so
  it can never be paired with the wrong account.

`accounts.server_for_user(plex, user_id)` returns the admin server for
`user_id == 0`. Otherwise it tries three sources in order and returns the
first that connects, because a server refuses an admin-issued token for a user
it has shared nothing with:

1. `connect_as_shared_user`: `user.get_token(machineIdentifier)` (**never**
   `switchHomeUser()`, which only works for Plex Home and raises 401 for
   ordinary shared users)
2. a token already in the store, under any candidate username
3. `MyPlexAccount(username, password)` for the `users` entry's username with
   its saved password, whose token is then **saved** so the login happens
   once

Each stage returns None rather than raising, so the next is tried and a stale
stored token falls through to a fresh login. Stage 3's sign-in is
`_login_entry`, shared with `configured_accounts()`, which yields each
`users` account signed in - by its stored token while plex.tv accepts it,
else by its saved password, saving the token - one at a time, so a caller
that finds its account early signs in no more. When all three fail, raise
`UserAccessError` explaining that admin rights do not override per-user
scoping and that a `users` entry signed in once with `login --username`
would fix it. It must be an ordinary `Exception`, **not** a `sys.exit`:
`playlist-copy --all` catches per-user failures and continues, and
`SystemExit` would tear down the whole run. `cli.main` converts it to a
clean exit for single-user commands. It carries a one-line `summary` so a
loop reports each skip in one line.

### Moving from 1.x

plexdo 1.x read `~/.local/etc/plexdo.ini` (`%LOCALAPPDATA%\PlexDo\plexdo.ini`
on Windows), with passwords and PINs in plaintext, and kept tokens in a JSON
file at its `token_path` (a pre-1.0.4 file holds one bare token, the
admin's). `migrate.migrate_legacy_config()` runs from `cli.main` before every
command, `--dry-run` included since nothing on the server changes, and does
nothing once `config.yaml` exists or when there is no INI file. Otherwise:

1. read the INI with `interpolation=None`, so a `%` in a password does not
   raise, and its token file;
2. merge tokens, passwords (the `[plex]` one filed under `[plex] username`;
   one with no username is dropped with a warning), and PINs into the
   secret store, a secret already saved winning as the newer;
3. write `config.yaml` with `config_text`, exclusively and mode 0600;
4. rewrite the INI without `password` or `pin` as `plexdo.ini.migrated`,
   headed by a comment saying where it went, remove the original, and
   delete the token file;
5. warn once, saying what moved where.

Secrets are saved before anything is removed, so an interrupted run loses
nothing and the next finishes the job.

## IDENTIFIERS

`identify.resolve_identifier(roster, value, kind, list_command)` implements
the rules once for users, libraries, and shows. Do not write it three times.

- Titles match exactly first, then case-insensitively.
- More than one title match aborts, listing the colliding IDs.
- A numeric value that is a real ID wins; if it is *also* another entry's
  title, warn naming the entry not selected.
- A numeric value that is not a real ID but is a title resolves by title.
- A numeric value matching nothing is returned unchanged, so the downstream
  lookup produces the precise error.
- A non-numeric value matching nothing aborts, pointing at the list command.

The duplicate-title abort applies only when resolving by title; a numeric ID
is unambiguous and must still work on a server with two identically titled
entries.

Every argument naming a user or library accepts either form, so those argparse
arguments are plain strings with `metavar="USER"` or `"LIBRARY"` - never
`type=int`. `accounts.resolve_user_arguments` and
`sections.resolve_library_arguments` run from `cli.main` after connecting and
before dispatch, rewriting `user_id`, `user_a`, `user_b`, `source_user_id`,
`dest_user_id`, and `library_id` in place, so handlers always receive an int. Build each
roster once per invocation, and skip the fetch when no such argument is
present.

## GLOBAL FLAGS

`-f/--format`, `--json`, `-v/--verbose`, `--debug`, `--debug-log PATH`,
`--dry-run`, `-W/--wide`, `--throttle`, `-V/--version`. They must work
**either before or after the command name**.

Implement with `_add_global_flags(parser, suppress=False)` called twice: once
on the top-level parser with ordinary defaults, and once on an
`add_help=False` parent that every subparser inherits via `parents=`.

The SUPPRESS default is essential, not cosmetic. A subparser parses into its
own namespace and then copies **every** attribute onto the main one, so
ordinary defaults on the inherited copies would silently clobber a flag given
before the subcommand: `plexdo --json users-list` would print a table.

Add them to an argument group titled `global options`, in order of their
long names, on both parsers. argparse carries a parent's groups over by
title, so every command's help lists them apart from its own options.

`--format` writes to `dest="format"`; `--json` is a `store_const` alias
writing to that same destination, so there is one attribute and no way for the
two to disagree. All logging goes to stderr only, or to the `--debug-log`
file; never to stdout.

### The debug log

`--debug-log PATH` sends everything `--debug` would show to PATH instead,
and stderr keeps the level it would have without `--debug`; `--debug` is
not needed with it. `logs.open_debug_log` opens it with `os.open`,
`O_APPEND | O_CREAT`, mode 0600, so a new file is its owner's alone and
earlier runs are kept, and line buffered, so a killed run loses nothing it
logged; a path that cannot be opened is a `sys.exit` naming it, before the
command runs. Expand `~`.

`TimestampedFormatter` starts **every line**, not every record, with
`time.time_ns()` at the moment it is formatted, then `LEVEL logger:
message`; a traceback or a cProfile table carries the stamp on each line.
`LogRecord.created` is a float and cannot hold nanoseconds at today's epoch,
so it is not used.

`profiling.profiled(enabled, command)` is the context `cli.main` runs the
command in, after `scrub_password_argument` so no `--password` reaches the
run start line: a `profiling.Run` with `--debug-log`, `nullcontext()`
without. `profiling.span(name)` times one phase - `migrate`, `connect`,
`resolve-arguments`, `command:NAME` - and is a no-op with no Run active.
The Run writes, as `key=value` pairs so the file is as easy to grep as to
read:
- `plexdo.profile: run start` - plexdo, Python, plexapi, and requests
  versions, platform, pid, command, `json.dumps(sys.argv)`;
- `span` lines - wall, CPU, user and system time, `cpu_percent`, memory,
  and the HTTP calls and wait inside the span;
- `plexdo.http: send` / `recv` / `fail` - Run replaces
  `requests.Session.send` for the run and restores it after, so every
  session, plexapi's included, is seen. `send` has an id, method, URL,
  body size, and headers; `recv` the status, reason, `wait_ns` (send to
  whole response, by `perf_counter_ns`), `headers_ns` (requests'
  `elapsed`), body size and type, and headers; `fail` the error, before
  re-raising. Never read the body of a `stream=True` response, which would
  consume what `read` streams: give its Content-Length. A redirect comes
  back through `send`; a thread-local depth keeps the nested hops out of
  the totals, so no wait counts twice;
- `resources` every `SAMPLE_SECONDS` (5) from a daemon thread, over the
  interval since the last;
- `run end` - status (`SystemExit` code, `interrupted`,
  `exception:TYPE`), totals, the HTTP count, wait, its share of the run,
  and the slowest request, then cProfile's top `TOP_FUNCTIONS` (40) by
  cumulative and by own time. Python 3.12 allows one profiler at a time,
  so `enable()` raising `ValueError` is logged and the run goes on
  without the tables.
CPU is `time.process_time_ns()` with `os.times()` for the user/system split.
Memory without a dependency: current RSS from `/proc/self/statm` on Linux
and `GetProcessMemoryInfo` through ctypes on Windows, the peak from
`resource.getrusage` (`ru_maxrss`, KiB except bytes on macOS) or Windows;
Linux updates the peak lazily, so report at least the current figure, and
`None` where the platform gives nothing. psutil would be a dependency for
one feature.

Redaction is in `security`. Both handlers, stderr and file, use
`RedactingFormatter`, which redacts the **whole formatted record**,
traceback included, since urllib3 logs request lines with their query
string and requests' exceptions quote URLs. `redact` replaces: the value of
any `name=value`, `name: value`, or quoted-key pair whose name is a token,
password, passwd, secret (as a suffix: `X-Plex-Token`, `authToken`), `pin`,
`X-Plex-Pin`, `X-Plex-Code`, `verificationCode`, `Authorization`, or a
cookie header, its scheme with it; the password in `scheme://user:pass@`;
and every value `hide_in_logs` was given. That registry is fed by
`secret_store.load` and `save`, the password prompt and
`scrub_password_argument`, and `hide_request_secrets`, which `send` calls
before the request goes out with the secret-named query parameters and
headers, a Basic credential's decoded password included. Values under 8
characters are not registered: a four-digit PIN would blank out every
matching number; named, it is still redacted. Bodies are never logged,
only their sizes. Name the registry what it is (`_KnownSecrets`), per the
naming rule above.

## OUTPUT

`output(data, args)` dispatches on `output_format(args)`, accepting **either**
a single record or a list so `metadata` and `library-list` share the path.
No command reaches for `json.dumps` directly.

### Formats

| format | notes |
| --- | --- |
| `table` | box-drawn, width-aligned, fitted to the terminal |
| `json` | non-ASCII escaped, so it prints on any console |
| `yaml` | strings **always** double-quoted |
| `csv` | header row, `\n` line endings |
| `clixml` | PowerShell CLIXML with typed properties |

- YAML strings must always be quoted. Plain style would let YAML's type
  guessing turn a title of `NO`, `yes`, or `1.10` into a boolean or a float on
  the way back in. The emitter must be recursive, or nested sections
  serialise as stringified Python dicts.
- CLIXML emits typed elements (`<S>`, `<I32>`, `<B>`, `<Nil>`) inside `<MS>`,
  the first `<Obj>` carrying `<TN>` and later ones `<TNRef RefId="0" />`,
  which is what `Import-Clixml` expects.
- `formats._cell_value` flattens for CSV and CLIXML; `records._jsonable`
  preserves structure for the formats that can express it.
- A command that reports as it goes emits through `console.stream_record`
  instead of `output`: JSON becomes JSON Lines, YAML a `---` separated stream,
  CSV a header before the first record only. **Flush every record**, or a pipe
  sees nothing until the buffer fills. CLIXML cannot stream - `Import-Clixml`
  reads exactly one document - so `STREAMABLE_FORMATS` leaves it out and such
  a command refuses it, pointing PowerShell users at `ConvertFrom-Json`.

### Tables

- `clean_text(value)` is `str(value).strip()`. Plex metadata contains stray
  `\r`, which makes a printed row's trailing pad overwrite the start of the
  line and appear as a blank line after every row.
- `_display_width` uses `unicodedata.east_asian_width`, **not** `len()`: CJK
  glyphs occupy two columns and combining marks none, so a `len()`-padded
  table drifts out of alignment on any non-Latin title.
- `_box()` test-encodes the glyphs against `sys.stdout.encoding` and falls
  back to ASCII `+-|`. A legacy Windows console is cp1252, which cannot encode
  U+2500, and the Unicode-only version raises `UnicodeEncodeError` and prints
  *nothing*. `_printable()` substitutes unencodable cell characters. Apply it
  only in the printers, never in `clean_text`, which feeds title matching:
  mangling an accented name there would break comparisons against real Plex
  data.
- `table_limit(args)` returns the column budget, or `None` when `-W/--wide` is
  given **or stdout is not a tty** - truncating a pipeline would corrupt data
  going to a file or `grep`. `_fit_widths` shrinks the widest column
  repeatedly, stopping at `MIN_COLUMN_WIDTH` and only then at the ellipsis
  itself, so a very narrow terminal degrades rather than overflowing.
  Truncation is display-width aware; report the narrowed columns once at info
  level naming `--wide`.

## THROTTLING

`throttle.paced(items, args, what)` yields items, sleeping `--throttle`
seconds between them once the count passes `THROTTLE_THRESHOLD` (50). Default
0.25s; 0 disables. The pause goes *between* elements, so n items wait n-1
times, and a short run is never paced because the delay would be latency for
no benefit. Announce once at info level with the expected duration and how to
turn it off.

Apply wherever a loop makes one request per element and the count can exceed
50: the seasons walk in `library-list`, `find-missing -A`, applying watched
state in `show-watched-cp`, removing entries in `playlist-clean`, reading each
source of `playlist-build --merge`, `collect_photos`, the walk of a show library in
`collect_library_items`, and the per-user loop in
`fanout.run_per_user`, which serves `playlist-copy --all`, and
`playlist-build` given `-a`. Functions needing it take an optional `args`.

## RECORDS

plexapi exposes `media`, `genres`, `directors`, `collections` and a dozen
others as `cached_data_property`. Those are **absent from `vars()`** until
something first accesses them, so reading only `vars()` reports a fraction of
the metadata and no file paths at all. Take the union of `vars(item)` and
`type(item)._cached_data_properties`.

Reading them must not cost requests, though:
`PlexPartialObject.__getattribute__` reloads whenever a value is `None` or
`[]` and the object is partial, which across a library is one round trip per
item. Set `item._autoReload = False` while reading and restore it afterwards;
that flag short-circuits the reload. Note plexapi returns underscore
attributes without reloading, so a test fake modelling this must explode only
for public names.

`records._media_versions` reads the XML plexapi already holds in `_data`
rather than the `media` property: it is always accurate, needs no reload
guard, and carries the `selected` flags that identify the version and part a
session is actually playing.

`_jsonable` expands nested plexapi objects to a depth of 2 rather than
`str()`-ing them, or `media` serialises as `<Media object at 0x...>` and the
file names appear nowhere. Cap the depth and guard `vars()` with `TypeError`,
since a self-referential object or one using `__slots__` would otherwise
recurse or raise. Reduce tag objects to their `.tag` and dates to text.

`records.file_paths(item)` is the **only** media traversal in the project:
M3U export, the photo gallery, `metadata`, and `loaded_fields` all use
it. An item may have several versions each with several parts, so it returns a
list. `loaded_fields` also lifts the paths to a top-level `files` key, because
they are otherwise three levels down.

`sourceURI` is not a file name: plexapi sets it from the `source` attribute,
the remote server URI of an item in another user's playlist, null for local
content.

## PLAYLISTS

Every argument naming an **existing** playlist accepts a title or a ratingKey
through `resolve_playlist`; no command may call `plex.playlist(name)`
directly. What counts as a ratingKey is decided by `titles.as_rating_key`,
**ASCII digits and nothing else**: `int()` is too generous a test, taking
`1_000`, `+7`, ` 12 `, and digits of other scripts, any of which may be what
a playlist is called. A numeric value that is no item at all is a clean `sys.exit`, not
plexapi's `NotFound` escaping as a traceback: look it up with
`titles.find_item`, which returns None, and `fetch_item` wraps that for every
other fatal lookup, `fetch_show` included. Nothing calls `fetchItem` bare.

Every command that creates a playlist constructs the list fully in memory, validates it is
non-empty, prints a numbered preview, and makes exactly one `createPlaylist`
call. `finalize_playlist` enforces this and returns `"created"` or
`"replaced"`.

There are two ways in: `finalize_playlist`, which **exits** on a refused name
collision, and `create_for_user`, which **reports** one as
`("skipped", detail)`. Both ask `_refuses_replacement` and both write through
`_write_playlist`, so the rule and the write each exist once. The second must
not `sys.exit`: it runs once per user, and SystemExit would tear down a run
that still had other users to serve - the same reason `UserAccessError` is an
ordinary exception. `require_items` holds the empty check, asked once by
whichever caller assembled the list rather than once per user.

Every creating command takes `-o/--overwrite`. A name collision without it
exits reporting the existing ratingKey and making clear nothing was created or
removed, and that check happens **before** the preview so a doomed run fails
immediately rather than after a screen of output.

`copy_playlist_to` returns `(status, final_name, detail)` and must **not**
delete: `_resolve_dest_name` only reports a replacement when `--overwrite` was
given, so `finalize_playlist` doing it too would be the same logic twice.
Without `--overwrite`, a taken name falls back to appending `" admin copy"`;
if that is taken too the target is skipped with a warning and nothing is
touched.

## COMMAND NAMES AND HELP

A command is named `<object>-<action>`: what it acts on, then what it does
to it (`playlist-list`, `playlist-export`, `libraries-list`). Plural objects
list many (`playlists-list USER`), singular ones show one (`playlist-list
USER PLAYLIST`). The exceptions are fixed names, kept exactly:
`show-watched-cp`, `find-missing`, `titles-export`, the
single words (`metadata`, `search`, `read`, `rescan`, `status`, `wait`,
`login`, `logout`), and `player-remote-play`, `set-pin`,
`write-config-example`, and `write-secrets-example`. 3.0.0 called two of
them `missing-find` and `show-metadata`; the next release named them
`find-missing` and `metadata`, again with no alias. There are no aliases:
one command, one name, so `COMMANDS` has exactly one entry per command.

Releases up to 2.1.0-rc.1 named commands `<action>-<object>`. 3.0.0 renamed
them, an incompatible change and so a MAJOR one, and also
folded `build-interleaved`, `build-chronological`, `build-randomize`, and
`append-playlist` into `playlist-build`, and `copy-playlist-all-users` and
`copy-playlist-to-user` into `playlist-copy`, and removed
`build-concatenated` and `list-titles` (whose alias `list-library` became
`library-list`). None of the old names is accepted.

`plexdo --help` lists the commands under five headings, in this order, and
sorted by name within each. `commands.GROUPS` is that list, and every
command must be in exactly one group (a test holds it to the registry):

| Group | Commands |
| --- | --- |
| libraries and titles | `album-list`, `find-missing`, `libraries-list`, `library-list`, `metadata`, `search`, `show-list`, `titles-export` |
| playlists | `playlist-build`, `playlist-clean`, `playlist-copy`, `playlist-export`, `playlist-list`, `playlist-remove`, `playlists-list` |
| playback and watched state | `player-remote-play`, `read`, `show-watched-cp`, `wait` |
| server | `rescan`, `status`, `users-list` |
| account and configuration | `login`, `logout`, `set-pin`, `write-config-example`, `write-secrets-example` |

argparse can only print subcommands as one flat list in registration order,
so pass `help=argparse.SUPPRESS` to `add_subparsers` and build the grouped
list into the parser's description, with `RawDescriptionHelpFormatter`:
the name padded to the longest, then the summary each `add_parser(help=...)`
gave, wrapped to 79 columns with a hanging indent. Give `add_subparsers`
`prog="plexdo"` and the parser `usage="%(prog)s [global options] <command>
[arguments]"`; without the first, every command's usage line repeats the
top-level usage. Summaries are one sentence, in the imperative, short
enough to fit their line. Positional metavars are upper case (`USER`,
`LIBRARY`, `PLAYLIST`, `NAME`, `QUERY`, `PATH`) except `ratingKey`, which is
spelled as Plex spells it.

After registration, `cli._tidy_command_help` goes over every command: it
sorts the `global options` group last, since a parent's groups otherwise
come before the groups a command adds, and, where a command set no `usage`
of its own, formats one from the command's own actions and appends
`[global options]`, so nine inherited flags do not bury the two that
matter. Both reach into argparse's protected attributes, which has no
public way to do either; keep that in the one function.

`playlist-build` and `playlist-copy` take a flag that decides what their
positional arguments mean, which argparse cannot express. They collect the
positionals unnamed, set `check_arguments` with `set_defaults` to a
callable taking the namespace, and `cli.parse_arguments(parser, argv)`,
which `main` uses in place of `parse_args`, runs it: the callable names the
arguments for the mode (`args.user_id`, `args.name`, `args.rating_keys`,
...) or calls `parser.error`, exit 2. That happens before anything connects
and before user titles are resolved, so `resolve_user_arguments` finds
`user_id` where it expects it. Each has a hand-written multi-line `usage`
and a description saying what each mode takes.

## COMMANDS

### Listing and searching

- `libraries-list` - columns `id`, `type`, `title`; writes the libraries cache.
- `library-list LIBRARY [-t TYPE] [--filter F=V]... [--category C]...
  [--list-categories] [--path PATH] [--album A]` - lists one
  type of item. `libraries.LIST_TYPES` gives, for each section type, the
  types Plex serves for it through `/library/sections/ID/all?type=`, the
  default first: `movie` (movie, collection), `show` (show, season,
  episode, collection), `artist`, a music library (album, artist, track,
  collection), `photo` (album, photo, clip). `-t` choices are their union
  plus `folder`; one the library cannot hold is a `sys.exit` naming those
  it can. Kept as a table rather than asked of the server's
  `filterTypes()`, which costs one or two requests a listing. Every type
  but `album` is `section.all(libtype=TYPE)`, which plexapi sends as
  `?type=N` with no validation request. `--album` lists photos through
  `collect_photos` and implies `-t photo`; `--path` implies `-t folder`;
  either with another `-t`, or the two together, is a usage error through a
  `check_arguments` hook. `--album` outside a photo library is ignored with
  a warning, as before.

  A table row suits the type (`_table_row`): `ratingKey`, `title`,
  `releaseDate`, `rating`, `studio` for movies, shows, and artists; an
  episode adds `show`, `season`, `episode`; a season `show`, `season`; a
  track `artist` (its own `originalTitle`, else the album artist), `album`,
  `track`; seasons, tracks, photos, and clips show `date` in place of the
  last three; a collection `items`. A machine-readable format carries every
  listed field and, for shows, nests each show's episodes under a `seasons`
  object keyed by season name. Write the completion cache, minimal
  `ratingKey`/`title` rows, **only for the default listing** with no
  `--album`, so what completion offers does not change with whatever was
  listed last; for a photo library that is its albums, which is what
  `--album` completion offers.

  `album` goes to `albums.list_albums(section, args)`, which outputs and
  returns the albums: the albums of a music (section type `artist`) or
  photo library. Music
  albums come from `section.albums()`. A photo library is walked depth
  first from `section.all()`, opening each album with one
  `fetchItems(f"{album.key}/children")` and splitting the children by
  `TAG == "Directory"` into nested albums, walked next so they follow their
  parent, and contents; a ratingKey met twice is listed once. Table
  columns are `ratingKey`, `artist` (music only), `title`, `year`, `items`,
  `played`; a music table reads `leafCount`/`viewedLeafCount` from the
  listing and opens no album. Every other format, and every photo listing,
  opens each album through `paced`. A machine-readable record carries
  `ratingKey`, `artist`, `title`, `year`, `items`, `duration`, `state`,
  `played`, `playedItems`, `inProgressItems`, `lastViewedAt`, `progress`,
  and `contents`; each content record `index`, `ratingKey`, `type`, `disc`,
  `track`, `title`, `artist`, `duration`, `state`, `played`, `viewCount`,
  `lastViewedAt`, `viewOffset`, `progress`, `files`. Every key is always
  present, null where it does not apply. Fields are read from `vars()`, so
  nothing reloads. An item has a state only if it carries `viewCount`
  (tracks and clips; photos do not): `in progress` when `viewOffset > 0`,
  even if played before, else `played` when `viewCount > 0`, else
  `unplayed`. An album is `in progress` if any item is, `played` if every
  playable item is, `unplayed` if none is, else `in progress`; null with no
  playable item. `progress` is a percentage to one decimal, null unless the
  state is `in progress`: an item's resume point over its duration; an
  album's played running time (played items in full, items in progress up
  to their resume point) over the total of its playable items. `viewOffset`
  is likewise null unless in progress.
- `--filter FIELD=VALUE` (repeatable) narrows any listing but a folder's
  through plexapi's `filters=` argument, which validates the field against
  the library's own filter list (one or two requests) and sends Plex's
  `/all?type=N&field=value`, or for several its advanced search. So any
  field the library offers works, tags and dates and numbers alike, and the
  error for one it lacks is plexapi's, which names the fields it has: catch
  `NotFound` and `BadRequest` around the listing and exit with its first
  line, prefixed "Cannot filter library 'X':", rather than letting the
  top-level handler call it a refused request. `parse_filter` is the
  argparse type: `FIELD` (letters, then letters or digits), an operator,
  and a non-empty value, `=` as is, `!=` as plexapi's `!`, `>` as `>>`,
  `<` as `<<`; anything else is a usage error. Several are joined as
  `{"and": [...]}`, so every one must hold. `--category NAME` (repeatable)
  is exactly `--filter genre=NAME`. `--list-categories` lists
  `section.listFilterChoices("genre", libtype)` as one `category` record
  each, in place of the items. A photo library's `album` is plexapi's
  `photoalbum` for both. Filtered albums come from
  `section.search(libtype=..., filters=...)` in `list_albums`, without
  walking into nested photo albums, which the server's filtering does not
  do. All three are usage errors with a folder listing or `--album`, and
  `--list-categories` takes neither of the others. A filtered listing is
  not cached.
- `-t folder` lists `/library/sections/ID/folder`, and `--path A/B` opens
  folder `A`, then `B` inside it, one request a level (`list_folder`).
  The XML is read with `plex.query` and walked directly: plexapi's `Folder`
  class drops the media items a folder holds alongside its subfolders. An
  element with no `ratingKey` is a subfolder, matched by title exactly
  before ignoring case; anything else is an item. Each record is `type`
  (`folder`, or the item's type), `ratingKey` (null for a folder), `title`,
  and `path`, the `--path` that opens a folder (null for an item). A folder
  not found is a `sys.exit` naming those there are.
- `album-list RATINGKEY` (also `commands/albums.py`) - one album, by
  `fetch_item` and one `/children` fetch. Refused with exit 1 unless the
  item is a Directory whose `type` is `album` (music) or `photo` (a photo
  album; a photo shares the type but not the TAG), since shows, seasons,
  and artists are Directories too. Nested photo albums are split off,
  logged at INFO, and counted in the table summary as `nested albums`, not
  listed. JSON and YAML output the same `album_record` as `library-list`;
  CSV and CLIXML output its `contents` alone. A table prints the album as a
  metadata block with only the keys that apply (`ratingKey`, `artist`,
  `title`, `year`, `items`, `nested albums`, `length`, `state`, `played` as
  "N of M", `in progress`, `progress` as "P%", `last played`), a blank
  line, then one row per item: `#`, `ratingKey`, `track` (as `2-03` when
  the album spans several discs; music only), `title`, `artist` (only when
  some track's artist differs from the album's), `length`, then, unless the
  album holds photos alone, `state`, `progress` ("3:20 / 9:46 (34.1%)" for
  an item in progress, else empty), and `last played` as a date.
- `show-list RATINGKEY [--m3u P] [-p PREFIX]` - fails fast if not a `Show`.
- `users-list` - `id`, `type`, `title`, `username`, `email`, from
  `accounts.user_rows`, which the `users` section of `status` shows too, so
  the two cannot come to differ; the command once printed three of the
  five while its documentation promised all of them. `account_type`
  returns managed/home/friend/shared. plexapi exposes `restricted` as the raw
  XML **string**, so `"0"` is truthy and a naive check labels every account
  managed.
- `playlists-list USER`, `playlist-list USER PLAYLIST [--m3u P] [-p PREFIX]`.
- `metadata RATINGKEY` - type-specific builders via `_METADATA_BUILDERS`
  keyed on `item.type`, plus the file paths. A table names a lone file `file`
  and numbers several `file 1`, `file 2`; other formats carry a `files` list.
- `search USER QUERY [--media-type T] [--library-id L]` - with
  `--media-type`, search only the libraries whose section type can hold it
  (`episode` in `show`, `track` and `album` in `artist`): asked for a type
  it cannot hold, plexapi raises "Unknown libtype", once per library. A
  library named with `--library-id` that cannot hold the type is a
  `sys.exit`. A library whose search raises is skipped, logged at DEBUG,
  and the rest are searched; the failures are reported, as **one** warning
  starting `Search failed in`, **only when no result came back at all**.
  With results in hand a library that could not be searched is noise.
- `find-missing SHOW [-l LIBRARY] [-A] [-s SEASONS] [--include-specials]` -
  names one show by default, resolved through `resolve_identifier`. A SHOW
  written as a ratingKey is fetched outright first, and used if it is a
  show: listing every show of every library to look up a number was the
  slow part. One `section.search(title=..., libtype="show")` per show
  library is still made, to give the usual warning when another show is
  *titled* that number ("24", "1923"). A number that is no show's key falls
  through to the roster, where it may be a title. `-A`
  sweeps every show and refuses a SHOW argument; `-s` takes one number or a
  comma list and applies only to a single show. For each season the run starts
  at 0 when an episode 0 exists and otherwise at 1, ending at the highest
  present. A season that simply **stops early is not a gap**: an unaired
  episode cannot be told from a missing one. Season 0 is skipped by default
  because specials are numbered irregularly, but `-s 0` overrides that, since
  asking for season 0 can only mean the specials. With nothing missing a
  table prints `No gaps found.`, but a machine-readable format prints an
  empty list: prose on stdout breaks whatever parses it.

### Building and copying

- `playlist-build (-I | -C) NAME RATINGKEY...`,
  `playlist-build -R USER SOURCE DEST`,
  `playlist-build -A USER PLAYLIST RATINGKEY...`,
  `playlist-build -M USER NAME FIRST SECOND` - one command, five modes,
  as a required mutually exclusive group of `store_const` flags writing
  `dest="mode"`. The positionals are `operand` and `operands` (`nargs="+"`), both
  shown as `ARG`, so that an option between the first argument and the
  others still parses; `_check_build` names them for the mode. The wrong
  count for the mode, or a ratingKey that is not an integer, is a usage
  error, exit 2, as is `-A` with any of `-o`, `-u`, `-a`, `--m3u`, and
  `-p`, which only make sense for a playlist being created. With too few
  arguments for `operand` and `operands` at all, argparse reports only "the
  following arguments are required: ARG", before any flag is looked at;
  the parser's `error` is wrapped to say instead what each mode takes,
  naming together the modes that take the same ("-I and -C take ..."). `-A` is
  `--append`; `-a` stays `--all-users`.
  - `-I/--interleaved` - round-robin across shows.
  - `-C/--chronological` - sorted by air date. A missing date
    is estimated from neighbours in the same season: collect up to 6 either
    side, require at least 3 known dates (so at least 2 intervals), take the
    median interval, estimate from latest-previous `+median` and
    earliest-next `-median`, averaging when both exist, and prompt only when
    that is impossible. A film with no date has no neighbours, so it is
    prompted for directly. `prompt_for_date` takes **any** item: name an
    episode by show, season, and episode, with `??` for a number Plex lacks
    rather than `00`, which would read as a real episode 0, and anything
    else by title and year. It once read episode-only attributes and crashed
    on every undated film. Running out of input is a `sys.exit` naming the
    item, not an `EOFError`.
  - `-R/--randomize` - Fisher-Yates via `secrets.randbelow`.
  - `-A/--append` - fetches every ratingKey as the user sees the server,
    exits 1 if any is not found, previews, then adds them in one call.
    Refuse a smart playlist before fetching anything, as `playlist-clean`
    does: plexapi raises `BadRequest` from `addItems`, which is also
    caught there and turned into a `sys.exit`.
  - `-M/--merge USER NAME FIRST SECOND [--ratio A:B] [-s] [-U]` - mixes two
    playlists in turn. It was the command `merge-build` until it was folded
    in here; `--ratio`, `-s/--stop-short`, and `-U/--unique` are refused, exit
    2, with any other mode, and `--ratio` defaults to None so a given one can
    be told from the default, 1:1, which `_check_build` fills in. The mode
    names its operands `user_id`, `name`, `first`, and `second`, which is why
    the unnamed positionals are `operand` and `operands`. It mixes A items
    from FIRST then B from SECOND, default 1:1, each keeping its own order. Parse the ratio in argparse (`type=`), so a
    bad one is a usage error, exit 2: two ASCII whole numbers above 0 joined
    by `:`. A side has run out on the first turn it has nothing to give; a
    turn cut short because fewer items were left still counts. From that turn
    the rest of the other follows by default, rather than being dropped, and
    `--verbose` reports how many items follow unmixed; `-s/--stop-short`
    leaves them out instead, the turn included, and reports how many. Sizes
    that match the ratio run out together, with no tail, so `-s` changes
    nothing. Repeats are kept; `-U/--unique` passes over an item already
    taken, by ratingKey, and the next item of the same side takes its place,
    so the ratio holds, and under `-s` a side left with only repeats has run
    out. `-U`, not `-u`: `-u` is `--user`, as on `playlist-build`. Read both
    sources before writing anything, so either may be the destination under
    `--overwrite`: the items are already in memory when the old playlist
    goes. Warn about an empty side rather than passing over it: a typo that
    resolved to the wrong playlist looks exactly like a playlist that happens
    to be empty.
- `playlist-copy -A USER PLAYLIST [-o]`,
  `playlist-copy -T USER PLAYLIST TO_USER DEST [-o]` - one command, two
  modes, as a required mutually exclusive group writing `dest="copy_to"`.
  The positionals are `source_user_id`, `source_playlist`, and `target`
  (`nargs="*"`); `_check_copy` requires none for `-A` and exactly two for
  `-T`, naming them `user_id` and `dest`, and anything else is a usage
  error, exit 2.
  - `-A/--all` - skips the source user, prints the
    item list **once** before the loop and passes `preview=False`
    thereafter, then one line per user (`created`, `replaced`, `skipped`,
    `failed`) printed as it completes. Because the caller surfaces the skip
    reason, the message inside `copy_playlist_to` is `LOG.info`, not a
    warning that would duplicate every skip on stderr.
  - `-T/--to` - a table shows the item list then the outcome line; a
    machine-readable format shows the outcome record **alone**, as `-A`
    does, because two documents on one stream parse as neither.
- `playlist-remove USER PLAYLIST` - names the playlist by its title in what
  it prints, however it was given. `--dry-run` says on stderr which
  playlist would be deleted, by title and ratingKey: a rehearsal that
  prints nothing cannot be told from one that found nothing to do, and
  every `--dry-run` must say what it would have done without `--verbose`.
- `playlist-clean USER PLAYLIST [--include-partial]` - removes the watched
  entries and leaves the rest in their existing order. Preview first, then one
  `removeItems` call per entry so the loop is paced like any other per-item
  loop; the playlist item IDs come from the listing plexapi already holds, so
  the repeated calls cost nothing beyond the one DELETE each. Number the
  preview by each entry's place in the playlist **as it stands**, not within
  the removal list, so it lines up with what Plex shows. A part-played item is
  **kept** by default - it is the one being watched right now, not a watched
  one - and `--include-partial` drops it, labelled `partial` rather than
  `played`. **The resume point is looked at first**: an item played before
  and part way through again has a view count and a resume point, and it is
  the second that says the user is in the middle of it. Refuse a smart playlist: its contents come from a filter, and Plex
  answers a delete on one of its entries with a 400. Warn when every entry is
  going, since Plex drops a playlist that loses its last item.

#### Who a built playlist is for

Every `playlist-build` mode but `-A` takes `-u/--user` and
`-a/--all-users`, registered through `fanout.add_user_target_arguments` as a
mutually exclusive group - writing the pair out on each parser is what trips
`duplicate-code`. Without either, the playlist goes to the account the items
came from, which is the admin server for `-I` and `-C`, which take rating
keys, and the source user's server for `-R` and `-M`, which take
playlists. `deliver_playlist`
takes both servers for exactly that reason. `-a` targets
`accounts.user_roster`, which **includes the admin** at id 0, because the
admin is a user of the server too.

`fanout.run_per_user` holds the loop: print the item list once, then run a
per-user action and print its one-line outcome as it completes, so a long run
shows progress; in a machine-readable format emit one record per user instead,
since one document cannot carry both. `playlist-copy --all` uses the same
loop with its own action and its own target list - the accounts a playlist is
shared with rather than the roster - so the loop is not written twice.

The action must turn every failure into a record rather than raising:
`UserAccessError` becomes a `skipped` carrying its one-line `summary`, a
refused name becomes a `skipped`, and anything else becomes a `failed` with a
`# pylint: disable=broad-except`. One bad user must never end a run that has
others left.

### Watched state

`show-watched-cp USER USER [-1] [-l LIBRARY] [-t KEY] [--unwatch]`.
`_select_winner(first, second, unwatch)` returns `(winner, loser)` or None:

| situation | default | `--unwatch` |
| --- | --- | --- |
| neither has data, or states match | skip | skip |
| exactly one has data | the one **with** it wins | the one **without** it wins |
| both have data | **latest** `lastViewedAt` | **earliest** `lastViewedAt` |

A `lastViewedAt` of `None` must never win: map it to `datetime.min` when the
latest wins and `datetime.max` when the earliest does. Plex rewrites
`viewOffset` continuously during playback, so treat offsets within
`_OFFSET_TOLERANCE_MS` (10s) as identical, or every run reports spurious
changes.

A state is two things, **the played flag and the resume point, and both are
copied as they stand**; the view count is used only to tell played from
not, and is never copied. So two states match when the flags are equal and
the offsets are within tolerance, whether or not the item is played: an item
played before and part way through again differs from one simply played.
Two fully played states with no resume point need no sync at all.

`_planned_steps(winner, loser)` gives the calls that bring the loser to the
winner's state, and the plan's `action` is those steps joined by `+`:
`markPlayed` or `markUnplayed` when the flags differ; else `clearProgress`
when the winner has no resume point and the loser has one; then
`setProgress` when the winner has one. Marking played or unplayed clears
the resume point on the server, so it comes **before** `updateProgress`,
and `clearProgress` is done by marking the item what it already is. It was
once applied only when the loser was fully played, so `--unwatch` planned
`markUnplayed` for an item one user was part way through, called nothing,
and reported the same change on every run.

`-t KEY` names what to compare. A movie, episode, track, or clip is
compared by itself. A show or season stands for its `episodes()`, an artist
or album for its `tracks()`, each member compared on its own: a
container's own played flag only says whether **every** member is played,
so comparing containers found two users at different points in a show
identical. Any other type is a `sys.exit` saying it has no watched state.

plexapi renamed these methods, so call through a helper trying both spellings
(`markPlayed`/`markWatched`, `markUnplayed`/`markUnwatched`) and read played
state from `isPlayed`, then `isWatched`, then `viewCount`. That read and the
resume-point read are `titles.item_is_played` and `titles.item_view_offset`,
because `playlist-clean` needs the same two and the rules must not be written
twice. All three attributes default to a bool or a number rather than None, so
reading them does not satisfy plexapi's reload condition.

Watch state lives on leaf items: map `movie`->`movie`, `show`->`episode`,
`artist`->`track`, and skip photo libraries. Use `section.all(libtype=...)`,
**not** `section.search(...)`, which needs a non-empty query.

### Exporting

- `playlist-export` and `playlist-list --m3u` are two ways to the same
  file, kept on purpose; both write through the one
  `commands.playlists._export_m3u`, so neither can write it differently.
- `playlist-export USER PLAYLIST PATH`, `titles-export LIBRARY PATH
  [--sort alpha|date|random] [--album A]`.
- M3U carries Plex server filesystem paths, `#EXTINF` seconds from
  `duration`/1000 with `-1` fallback, and skips items with no path.
- Photo libraries export a self-contained Spotlight.js gallery. **No Plex HTTP
  URLs anywhere in it**: both `href` and `src` are server filesystem paths.
- `-p/--prefix` on every command that exports (`playlist-list`, `show-list`,
  `playlist-export`, `titles-export`, `playlist-build`),
  registered through
  `paths.add_prefix_argument` - repeating the help text inline trips
  `duplicate-code`. `mapper_for(plex, args)` returns `identity` without a
  prefix, so the default costs no extra call. The prefix replaces the
  **library root**, so `library_roots()` sorts longest-first or a library
  nested in another's tree matches the wrong one. Rejoin using the prefix's
  own separator style. A path under no known root is appended whole and warned
  about exactly once.

### Photos

`photos.walk_photo_albums(section, args)` is the one walk of a photo
library, used by `library-list`'s album listing, its `--album`, and
`titles-export`. It
starts from `section.all()` and opens each album with one
`fetchItems(f"{album.key}/children")`, splitting the children by
`TAG == "Directory"` into nested albums, walked next so they follow their
parent, and contents. It returns an `AlbumVisit` per album: the album, its
contents, and the titles of the albums around it ending with its own. The
photos of an album inside another are in neither the library listing nor
the outer album's own children, so a walk that stops at the top level
loses them, as `collect_photos` once did.

Two guards, both needed. A ratingKey met twice is passed over: that lists
once an album the server shows at the top level as well as nested, and
stops albums that contain one another from being walked for ever. And
nesting is followed `MAX_ALBUM_DEPTH` (16) albums deep, since a loop check
cannot stop a server that keeps producing new albums; what lies deeper is
left out with **one** warning naming where the walk stopped.

`collect_photos` takes the `type == "photo"` contents of each visit,
leaving clips out. `--album` matches a title, ignoring case, against every
title in the visit's path, so naming an album takes the albums inside it
too, and an album nested anywhere can be named. A name matching no album
is a `sys.exit`; an album that exists and is empty is not.
**Never** `section.search(libtype="photo")`: Plex requires a non-empty query
string and returns nothing for an empty one, so the library appears empty.

### Streaming and server management

- `read RATINGKEY` - streams to `sys.stdout.buffer` in 64KB chunks via
  `requests.get(stream=True)`. It takes no library: a ratingKey is unique
  on the server, and an argument that only existed to be checked against
  the item was one more thing to look up and type.
  Catch `BrokenPipeError` silently and `os.dup2` the null device onto stdout,
  so the interpreter's final flush does not print "BrokenPipeError ignored"
  when the user quits the player. The epilog shows worked examples including
  `plexdo read 12345 | mpv --vo=drm -` for **Linux with a display attached
  but no desktop environment** - describe the condition, not the machine:
  "headless" contradicts having a screen, and the hardware could be a Pi, a
  kiosk, a sign, or an old laptop.
- `rescan LIBRARY [-n]`, `rescan -a [-n]`, `rescan -s` - `plex.activities`
  is a **property**, not a method. `section.update()` scans for files;
  `refresh()` only re-fetches metadata. `-a/--all` scans every library with
  the one `plex.library.update()` call. Exactly one of LIBRARY and `-a` is
  required without `-s`, checked by a `check_arguments` hook so it is a
  usage error, exit 2, before anything connects: with neither, the message
  says to name a library **or use `--all` to rescan every library**, so a
  library left off by mistake does not set the whole server scanning.
  `--dry-run` says on stderr what would be scanned, and whether pending
  scans would be cancelled first. `-s` with no activity prints
  `No active scan jobs.` on stderr as a table and an **empty list** in a
  machine-readable format.
- `status [--section S]` - the sessions table carries `sessionKey`, `user`,
  `library`, `ratingKey`, `title`, `state`, `player`, `platform`, `address`,
  `progress`, and `file`; `sessionKey` is what `wait --session` takes. `records.playing_file` reports the file in use: a session marks
  the version and part being played with `selected`, which is the only way to
  tell them apart on a multi-version item, and nothing is marked when there is
  just one, so an empty selection means all of them. Eight sections: `server`, `sessions`, `users`,
  `accounts`, `connections`, `scans`, `activities`, `tasks`. Split
  `plex.activities` on whether the type mentions scan/refresh/library so scans
  and other background work are separate. Collect each section in its own
  try/except: `connections` needs a plex.tv round trip an offline server
  cannot make. CSV and CLIXML are flat and require `--section`.

- `wait [-s KEY] [-r KEY] [-a] [-i S] [--fast-interval S] [--no-credits]
  [--offset S] [--paused S] [--now]` - sleeps until a play is over, then
  exits 0, so
  `plexdo wait && ...` runs afterwards. Follows the first session listed, or
  `-s`, and waits for what it is playing, or `-r`.
  - **The end point** is the start of the end credits when there is a credits
    marker and the video's end otherwise; `--no-credits` always uses the end.
    Take the marker Plex flags `final`, else the last: a film with a
    mid-credits scene has two, and the final one follows the scene. Read the
    markers from `_data`, as `records` reads media, after fetching with
    `fetch_item(..., markers=True)` - a plain fetch omits them, and touching
    `markers` afterwards costs a reload.
  - **The wait also ends** the moment the video stops playing, wherever it had
    got to: the session is gone, or has moved to another ratingKey because
    autoplay went on to the next episode.
  - **`--paused S`** counts a play as over once its player has sat paused S
    seconds. Plex gives no pause timestamp, so the count starts at the first
    poll that sees the pause, keyed by play - (sessionKey, ratingKey) - and
    any other state clears it. Compare rounded to the millisecond: a sleep
    timed to land on the deadline must count as reaching it despite float
    error. While paused, the estimate is the pause's time left.
  - **One judge:** `_assess` decides every play's state - reached, left
    paused, or the player's own - for both a single wait and `--all`, so the
    two cannot drift apart.
  - **`--all`** judges every session on its own video each poll, one line or
    record per session, reporting a play that has vanished once as
    `stopped`. Nothing pending must be seen **twice, a slow interval apart**,
    before it exits - the second poll is what catches a play started in
    between, autoplay's next episode included - and that holds even when
    nothing was playing to begin with. Fetch each video's markers once per
    ratingKey with `find_item`, which returns None rather than exiting:
    an item the server will not return falls back to the session's own
    duration and XML instead of ending a wait over everyone. Refuses `-s`
    and `-r`.
  - **Offset:** negative moves the end point that many seconds earlier,
    clamped at 0; positive is a sleep taken *after* the wait, not a position,
    since there is no playback left to watch past the end.
  - **Cadence:** `-i` (10s) until any unfinished play is within 30s of its
    end point or past it, then `--fast-interval` (1s); every delay jittered
    by up to 20% either way. A slow delay is cut short at the soonest moment
    any play next needs a look - its fast window, or its pause running out -
    so a long `-i` cannot sleep straight through either. Not `paced`: this is a
    timed poll, not a loop over elements.
  - **Following:** bind to the user of the session being followed, preferring
    its original sessionKey but accepting any of that user's sessions on the
    video, since stopping and restarting gives the same play a new key. `-r`
    without `-s` binds nobody until someone is seen playing the video; until
    then a poll describes the first session listed.
  - **Every poll** reports the user, what is playing, the video waited for,
    position, time waited, and estimated time left - one line for a table,
    one streamed record otherwise, each record carrying every key so CSV
    columns stay fixed. A video not yet playing says so and is waited for;
    `--now`, valid only with `-r`, exits 0 instead.
  - **Failure:** a failed poll is a warning and a retry, since a wait can last
    hours; five in a row is a `sys.exit`. Nothing playing at all is exit 0.
    An unknown `-s` exits 1 listing the active sessionKeys - a typo must not
    let `&&` run. Ctrl-C exits 130 for the same reason.
  - Time, sleep and jitter come in as one `Clock`, so the loop is tested
    without waiting.
- `player-remote-play HOST RATINGKEY [--port P] [--player-user USER]
  [--server-url URL]` -
  connects to the player itself with plexapi's `PlexClient` and calls
  `playMedia`, not proxied through the server, so the server need not know
  the player.
  - **IP only on the wire.** Some players refuse a Host header carrying a
    name, as a DNS rebinding defence, so resolve a name here with
    `getaddrinfo` and build every URL from the address; bracket IPv6. Try
    each address in the resolver's order until a player answers at
    `/resources`. Something answering without a `machineIdentifier`, or
    with a reply plexapi cannot parse, is not a player and the next
    address or port is tried; none answering is a `sys.exit` naming each
    URL, and suggesting `--port` when it was not given.
  - **The player's port.** Plex apps differ: 32500 Android/Fire TV, 8324
    Roku, 32433 Plex HTPC/Plex Media Player, 3005 Plex Home Theater,
    Plexamp anywhere. `--port` has no default and, given, is used as is.
    Without it, send a unicast GDM `M-SEARCH * HTTP/1.0` to UDP 32412 at
    each IPv4 address (2 s); a `200 OK` reply from that address whose
    `Content-Type` (if any) names a player gives the port to use. Silence,
    an IPv6 address, or an unusable reply falls back to `_KNOWN_PORTS` in
    the order above, each first checked with a 2 s TCP connect so dropped
    guesses do not each cost the 10 s probe timeout. Tests stub GDM and
    the connect check by default, and exercise both for real on loopback.
  - **Probe without a token**: what answers may not be the player, and a
    token is a credential. Only a 401 earns a retry with plexdo's token.
  - **Whom to send as.** A player trusts the account signed in to it. Send
    as plexdo's own account when it is the server's admin
    (`plex.myPlexUsername`, an email, matching its email or username,
    ignoring case) or when the player's machine identifier is among its
    plex.tv `devices()`; otherwise as the first `configured_accounts()`
    entry whose devices include the player; otherwise as plexdo's own
    anyway, with a warning naming the `users` entry fix. plex.tv being
    unreachable for any of this is a warning and plexdo's own token, never
    the end of the command.
  - **The sending account also fetches the item.** `playMedia` builds the
    play queue and mints the delegation token on `media._server`, and the
    player switches its user to whoever that is, so an item fetched as
    plexdo makes a Roku signed in as a managed user switch to plexdo's
    user. `_server_as` tries `connect_with_token` with the account's own
    token, then, since a server refuses a managed user's plex.tv token,
    `connect_as_shared_user` with the matching `current.users()` entry
    (the admin-minted server token every per-user command uses). Neither
    working is a `sys.exit` for `--player-user` (strict) and a warning
    saying the player will switch, then plexdo's server, for the
    automatic choice.
  - **`--player-user`** names the account instead - a plex.tv id, username,
    or email, ignoring case - and overrides every rule above, the admin
    shortcut included. plexdo's own account when it matches, or when the
    value is `0` and plexdo is the admin, since `0` means the admin
    everywhere else. Then a Plex Home member (`home` true in
    `current.users()`, managed users included) matching by id, username,
    or email, or by title when it has no username, as a managed user has
    none: `switchHomeUser(user, pin=)` gives its plex.tv account without a
    password, `pin` being the one `set-pin` saved; the switched token is not
    stored, as switching is cheap and needs no secret. A refused switch
    falls through to the `users` entries, and with none is a `sys.exit`
    naming `plexdo set-pin <id>`. Otherwise a
    `configured_entries()` entry whose id or
    username is the value is taken at its word without a sign-in to check;
    failing that, sign the rest in one at a time through
    `configured_account` and compare id, username, and email, because an
    entry may file the account under the email when given the username.
    Nothing to act as, or plex.tv unreachable, is a `sys.exit`: never send as
    some other account than the one asked for. Deliberately not in
    `USER_ID_ARGUMENTS`: the value is matched against accounts, not the
    roster, whose titles are display names rather than usernames.
  - **The fetch address** is `playback.fetch_address`, below.
  - A 401 from the player is a `sys.exit` explaining the account rule. A
    `ParseError` is success: plexapi parses only after checking the status,
    and some players answer a command with a bare `OK`.
  - `--dry-run` resolves, probes, chooses the account and the address, and
    sends nothing; choosing may still sign in a configured account. Output
    carries `player`, `machineIdentifier`, `product`, `host`,
    `playerAddress` (the URL used), `account`, `ratingKey`, `title`,
    `fetchFrom`, `status`.
  - Every library item plexapi returns carries a `listType`, or a playlist a
    `playlistType`, so `playMedia` accepts all of them; no type check is
    needed, and one would be dead code.

#### The address a player fetches from

`playMedia` tells the player to fetch from the media's server URL, plexdo's
configured one, which suits plexdo's network and not necessarily the
player's: plexdo often runs on another routed segment, or another IPv6 site.
`playback.fetch_address` chooses instead, and the command passes protocol,
address, and port to `playMedia`, whose `**params` override its own:

- Candidates: the configured URL, listed first, and every connection plex.tv
  lists for the server except relays, which are throttled below what video
  needs. Drop any whose address is loopback, link-local, unspecified, or
  multicast - for a plex.tv connection, test its bare `address`, not just
  its URI's host, which is a plex.direct name that says nothing.
- Name a plex.tv candidate by its URI's host, normally a plex.direct name
  over https, and rank it by its bare address: https to a bare IP fails the
  certificate.
- Rank against the player's IP, an IPv6-mapped IPv4 address read as IPv4:
  same family; then same scope by `ipaddress.is_global`, so RFC 1918, ULA,
  and carrier-grade NAT are private alike; then the longest shared prefix. A
  host name, family unknown, ranks between a family match and a mismatch.
  Scope outranks prefix: bits shared across the private/global line mean
  nothing. A tie keeps the first, the configured URL.
- Bracket an IPv6 literal sent as the address: the player joins address and
  port into a URL.
- Do not probe the chosen address. A probe runs from plexdo's network, which
  is the very network that may differ from the player's.
- `--server-url` bypasses all of it, loopback included, for a player on the
  server's own machine or networks joined by NAT; it must be an http or
  https URL with a host, port defaulting to 32400.
- With no candidate left, `sys.exit` asking for `--server-url` or a
  reachable `plex: url`. Show the address chosen in the output
  (`fetchFrom`).
- Tests must use genuinely global addresses for anything about scope: the
  documentation ranges, 2001:db8::/32 and 192.0.2.0/24 among them, are not
  global to `ipaddress`, and would leave the rule unexercised.

The ratingKey argument, `--server-url`, and the record's closing fields come
from `playback.add_play_arguments` and `play_fields`, so a second playback
command would not repeat them and trip `duplicate-code`.

### Setup

- `login [-u USER] [-p PASS] [--save-password] [-c CODE] [-2]` - the
  username is `--username`, else `plex: username`, else prompted for; the
  password is `--password`, else the one saved for that username, else read
  with `getpass`. The token is saved under the username (`ADMIN_KEY` with
  none), and `--save-password` saves the password beside it so plexdo can
  sign in again by itself once the token stops working. `--dry-run`
  authenticates and saves nothing. The table says where the token went
  (`secret_store.describe("tokens")`); other formats give `user`, `store`,
  `passwordStore` (`describe("passwords")`), `verified`, and
  `passwordSaved`. `--password` on the command line is
  scrubbed from the process title via `ctypes.pythonapi.Py_GetArgcArgv`
  (`sys.argv` is only a copy; `ps` reads the original buffer) and redacted
  from `sys.argv`, with a warning that is blunt about what cannot be fixed:
  the value is already in shell history and was visible during interpreter
  startup. On Windows the rewrite has no equivalent.
- `logout [-u USERNAME]` - signs each stored token out at plex.tv
  (`MyPlexAccount(token=...).signout()`) and removes it from the store via
  `tokens.forget_tokens`, **and removes the saved password** of each account
  signed out, which would otherwise sign it straight back in on the next
  command. `-u` names a store key, exactly then ignoring case; one the store
  lacks is a `sys.exit` listing those it has, since signing out nobody would
  read as success. A token plex.tv already refuses (`Unauthorized` on
  loading the account) is `already signed out` and removed; any other
  failure leaves the token valid, so it is **kept** for a retry and the run
  exits 1 after removing the rest. Sign a token filed under two names out
  once. `--dry-run` contacts nothing. Needs no server, so it works when the
  server is down.
- `set-pin USER_ID [--remove]` - prompts with `getpass` for a Plex Home
  member's PIN, four digits, an empty answer meaning none, and saves it
  under the numeric user id; `--remove` removes it without prompting. The
  id is not resolved against the roster, so no server is needed.
  `--dry-run` saves nothing.
- `write-config-example [-o]` - writes `CONFIG_EXAMPLE`, mode 0600. An
  existing config is refused without `-o/--overwrite`, and that check comes
  before `--dry-run`, so a rehearsal fails where the real run would; a
  dry run then writes nothing and says where it would write. Its `--help`
  prints the exact template, which needs `RawDescriptionHelpFormatter` for the
  epilog's newlines; that same formatter stops argparse wrapping the
  description, so pre-wrap it with `textwrap.fill(..., width=78)`.
- `write-secrets-example [-o]` - writes `constants.SECRETS_EXAMPLE` to the
  path `plex: secrets_file` names, after `expanduser`, creating its
  directory. **When `secrets_file` is not set, write nothing**: say so on
  stderr, naming the config path, and print the example to stdout, exit 0.
  A missing config file sets nothing, so it takes that path too rather than
  the "Config not found" exit; read the file with `parse_config` directly,
  not `load_config`. The default secrets path is deliberately not used:
  only a path the user chose is written to. An existing file is refused
  without `-o/--overwrite`, before `--dry-run` as for the config, because
  it may hold the only copy of a saved password or PIN. Create the file
  with `os.open(..., O_CREAT | O_EXCL, 0o600)`, unlinking an old one first
  under `-o`, so it is never readable by anyone else, even for a moment,
  and an overwritten file does not keep looser permissions. The example is
  the **password store**, the secrets file as `secret_store: file` keeps
  it: JSON as `FileStore` writes it (`indent=2`, sorted keys), with
  `passwords` and `pins`, each with one placeholder entry, and a
  `_comment` entry, a list of short lines, saying every value is a
  placeholder and that session tokens are not kept there. It must hold no
  `tokens`: a placeholder token beside a real one made the store hold
  two, so `admin_token` no longer took "the only one" and every command
  reported no admin token. JSON has no comments; `FileStore` reads only the kinds it
  is asked for and writes back every entry it loaded, so the note is
  harmless and survives a later save. Its `--help` prints the exact
  example in the epilog. Needs no server.

## ERROR HANDLING

`sys.exit` with a clear message for: missing or malformed config, missing
token, an unusable keyring, unknown
ratingKey, wrong media type, playlist or user or library not found,
unsupported library type, album not found, a refused name collision, a smart
playlist asked to give up an entry, an unknown sessionKey, an existing config
file without `--overwrite`, an air date with no input to answer for it, a
`logout -u` name not in the secret store, a player host that does not resolve
or where no player answers. A
command line argparse cannot parse exits 2, its own convention. An
interrupted `wait` exits 130. No bare
`except`; the broad ones are in `_cancel_all_scans`, the per-user copy loop,
the per-library search, and per-section collection, each with a
`# pylint: disable=broad-except`.

**A request that fails must not reach the user as a traceback.** `cli.main`
wraps `_run` and catches `requests.exceptions.RequestException` and
`plexapi.exceptions.PlexApiException`, the two families everything raised
by a request to the server or to plex.tv belongs to, and exits 1 with one
or two lines chosen by kind: the server could not be reached (check it is
running, and `plex: url`), it did not answer in time, it refused the saved
token (run `plexdo login`), or it refused the request. Only the **first
line** of the error is shown, since plexapi attaches the server's whole
HTML error page to some, and it goes through `security.redact`, since a
URL in a requests error can carry a token. The traceback is logged at
DEBUG. Handlers closer to the request, such as the per-user loops and
`UserAccessError`, still take precedence; this is the net under them.

## PLATFORM SUPPORT

- **macOS** ships bash 3.2, which has no `mapfile`; fill `COMPREPLY` with a
  `while IFS= read -r` loop, `_plexdo_compreply`, fed by process
  substitution: `COMPREPLY=(); _plexdo_compreply < <(compgen ...)`. That
  is also what ShellCheck's SC2207 asks for in place of
  `COMPREPLY=( $(compgen ...) )`, which splits a file name with a space in
  it into two candidates. Use `stat -c %Y` with a `stat -f %m` fallback.
  Restrict the Makefile to `install -d` / `install -m`; `install -D` is
  GNU-only.
- **Windows**: skip the POSIX permission check and `chmod`; the console
  encoding fallback above; `--password` scrubbing is best-effort only.
- **Secrets**: `keyring` picks the platform's store itself; on Linux and BSD
  it needs a Secret Service provider such as GNOME Keyring or KWallet on the
  session bus. A headless machine has none, so `auto` falls back to the
  file there.
- All completions fall back to `python` when `python3` is absent, as under Git
  Bash.

## SHELL COMPLETION

Four scripts in `completions/`, mirrored into `src/plexdo/data/` as package
data. All cover the same values, read a 15-minute cache under the platform
cache directory (honouring `cache_dir`), and refresh a stale cache in the
background so completion never blocks.

**Each script finds the cache as plexdo does**, or completion silently
offers nothing: `plex: cache_dir` from `config.yaml`, in
`$XDG_CONFIG_HOME/plexdo` or `~/.config/plexdo` (`%LOCALAPPDATA%\PlexDo` on
Windows), with environment variables and a leading `~` expanded; else
`$XDG_CACHE_HOME/plexdo`, by default `~/.cache/plexdo`. An XDG variable
counts only when absolute. They once read the 1.x INI file and a
hard-coded `~/.cache`, long after both had moved. PyYAML may not be
importable by whichever python the script finds, and PowerShell has no
YAML reader, so each reads the one scalar it needs a line at a time: a
`cache_dir:` line indented under the top-level `plex:` key, skipping
blank and comment lines, unquoting a double-quoted value as a JSON string
and a single-quoted one by its doubled quotes, and cutting a trailing
` #` comment from a plain one. bash, zsh, and fish share one python
snippet, which must contain **no single quote and no backslash**, because
fish holds it in a single-quoted string.

**The cache is kept twice, by ID and by word.** `titles.LIBRARY.json` and
`playlists.USER.json` are named for the numeric ID, but a script holds
whatever is on the command line, which may be a title, and cannot resolve
it as plexdo does. So `cache.write_word_caches` files the same rows as
`titles-by-word.WORD.json` and `playlists-by-word.WORD.json`, once for
each spelling: the ID, the title, and the word as typed.
`identify.remember_words` records the three while the argument is
resolved, on `args.argument_words`, since resolution replaces what was
typed with the ID; `argument_words(args, name)` reads them back. Both
caches are written whenever a result is handled, so they cannot drift. In
a file name `cache.cache_key` replaces each of `/ \ : * ? " < > |` and
the control characters with `_`, chosen so every shell can make the same
name with one substitution of its own; each script has that function and
a test compares them. Playlist and album-name completion read the by-word
cache for the word typed, dequoted. An album name is a whole title from
that cache, which for a photo library holds its albums, the default
listing; titles are no longer split at " - ", which mangled an album titled
with one. `library-list -t` completes the types, all of them, since the
library's kind is not known to the script; ratingKey completion still gathers
every `titles.*.json`, which the by-word names do not match, so no key is
offered twice.

Numeric IDs are shown with their titles. Distinguish what is *insertable* from
what is merely *shown*: user and library titles are insertable because those
arguments accept them, but an item title is not, since `fetchItem` needs a
numeric ratingKey.

- **bash** - no `bash-completion` package: initialise from `COMP_WORDS` and
  `COMP_CWORD`, use `compgen -f` not `_filedir`. Values that can contain
  spaces must reach `COMPREPLY` as whole lines via the read-loop helper, not
  through `compgen -W`, which splits `TV Shows` into two candidates. bash
  cannot attach descriptions, but it only *inserts* once a single candidate
  remains, so `_plexdo_compreply_pairs` lists annotated forms while a choice
  remains and substitutes the bare value when it collapses to one.
  `_plexdo_complete_rating_key` merges keys from every `titles.*.json`, so it
  must gather then render once and clear `COMPREPLY` on entry.
- **zsh** - `#compdef plexdo`, `_arguments -C` with `'*::arg:->subcmd'`. Note
  that under `*::` zsh **rebinds `words` so `words[1]` is the subcommand**.
  Sanitise `:` out of descriptions, since `_describe` splits on it.
- **fish** - no positional-index primitive, so walk `(commandline -opc)`,
  skipping options that consume a value. Guard the background refresh on the
  binary existing: fish reports an unknown command *before* redirection
  applies, scribbling on the prompt mid-completion.
- For `playlist-build` and `playlist-copy`, every script first finds the mode
  flag among the words already typed, and completes each positional as that
  mode defines it: with `-I` or `-C` a name then rating keys; with `-R` a
  user, then that user's playlists; with `-A` on `playlist-build` a user,
  that user's playlists, then rating keys; with `-T` on `playlist-copy` the
  receiving user third. With no mode typed yet, nothing says what an
  argument is, so bash offers the mode flags and the others offer only
  options. In zsh, hold option specs that use `{-o,--overwrite}` braces in
  **arrays**: a scalar assignment does not expand the braces, and the spec
  reaches `_arguments` malformed and is silently never offered.
- **PowerShell** - `Register-ArgumentCompleter -Native`. Compare the mode
  flags with `-cin`: PowerShell's `-in` ignores case, and `-a` and `-A` are
  different options. Needs no external
  interpreter: `ConvertFrom-Json` reads the cache. Return `CompletionResult`
  objects so the ID is inserted and the title shows as a tooltip. Two traps
  that parse cleanly and fail at runtime: a range of `0..-1` **wraps** and
  yields the whole array, and a parenthesised `if` is not a valid argument
  expression.

## MAN PAGE

`man/plexdo.1`, in roff, mirrored into `src/plexdo/data/`. Documents every
command, under the same five headings and in the same order as `--help`,
and the configuration and token formats, exit status, environment, files,
and worked examples, and passes `groff -man -Tutf8 -ww -z` with no warnings.

Escapes that silently corrupt copy-pasteable examples: a literal backslash is
`\e`, a literal apostrophe is `\(aq`, and a backtick is `\(ga`. groff remaps a
bare `'` to a typographic right quote on many configurations. Double quotes
are not remapped. Write URLs as plain text with `.I`, not with `.UR`/`.UE`,
which emit OSC-8 escapes that duplicate the URL wherever the page is piped
through something that does not understand them.

## TESTS

`tests/` holds a pytest suite that must pass in `make check`. It covers the
project's own decision logic and never touches a network; `conftest.py`
provides one `FakeItem`, one `FakeMedia`, and friends, and an autouse fixture
giving every test an empty in-memory secret store, so no test reads or
writes the keyring or secrets file of whoever runs it, and none fails on CI
for want of one. Likewise no test may read the developer's own
`config.yaml`: a test needing one writes it under `tmp_path`. Do not define a second
mock for a concept that already has one.

Worth testing, because a regression there is silent rather than loud: the four
serialisers round-tripping through real parsers; table alignment under
double-width characters, the ASCII fallback, and fitting to a budget;
identifier resolution including the ID-versus-title collision; the overwrite
guard performing **no** server calls when it refuses; watched-state selection
in both directions and that an undated state never wins; which playlist entries
`playlist-clean` drops, and that it numbers them by their place in the
playlist rather than within the removal list; that a merge keeps each side's
order and that `--unique` matches on ratingKey; that every command is in
exactly one help group, that `--help` lists them grouped and sorted, and that
the old names are refused; that each `playlist-build` and `playlist-copy`
mode names its arguments, and that the wrong count, a missing or second mode
flag, and `--append` with a creating option all exit 2; that
`write-secrets-example` prints rather than writes when `secrets_file` is not
set, refuses an existing file, writes mode 0600, and that its example loads
through `FileStore` with its note surviving a save; that a per-user create
reports a taken name instead of exiting and performs no call when it does, and
that a fan-out records an unreachable user and an unexpected failure and keeps
going; where `wait` puts its end point for every combination of marker,
`--no-credits` and offset, that it switches to fast polls 30s out and never
sleeps through that window, that it ends on a stop or on autoplay moving on,
that a failed poll is retried; that `--paused` ends a play on its deadline and
a resume restarts the count; and that `--all` waits for a play started during
its confirming poll, takes that second look even when nothing played, and
judges an unfetchable video by its session; that `logout` keeps a token it
could not sign out and removes one plex.tv already refuses; that
`player-remote-play` sends only IPs, probes without a token, and picks its
account by the rules above; that the fetch address follows family, then
scope, then prefix; path rewriting
picking the longest matching root; that the template is valid YAML stating
every option and its default; that the config refuses a secret and reports
an unknown option by name; that `auto` falls back to the file only without a
real keyring, and `file` never asks one; that the secrets file is private
from the moment it exists and goes with its last secret; that the 1.x
migration moves every token, password, and PIN, a legacy bare-token file
included, leaves no secret in plaintext, and keeps a secret already saved
over the old one; that `login --save-password` spares the next prompt;
that `logout` removes a signed-out account's saved password; that `set-pin`
takes four digits only; that `loaded_fields` and `file_paths` never trigger a reload; and that
global flags survive being given before the subcommand.

Each bug that shipped gets a regression test in `tests/test_fixes.py` that
**fails against the code before the fix**; check that it does, or it proves
nothing. Build real plexapi `Movie` and `Episode` objects from XML for these
where the bug was about their attributes - they construct offline - rather
than stand-ins that would have hidden it.

Two behaviours easy to get backwards: two fully played states need no sync, so
a "latest wins" test must use states that actually differ; and
`format_duration(None)` is empty while `format_duration(0)` is `"0:00"`,
because unknown and zero are different things.

## BUILD

`make check` runs, in order: `check-version`, `check-assets`, `smoke`, `test`,
`lint`, `build`, `dist-check`.

- `check-version` runs `tools/derive.py --check`: the man page's `.TH` line
  and the SBOM must match `pyproject.toml`. `make derive` rewrites them.
- `lint` runs `ruff check`, `ruff format --check`, pylint, ShellCheck,
  yamllint (the repository's YAML, and the template plexdo writes, piped
  in), markdownlint-cli2 through `npx --no-install` from `package.json`, and
  `reuse lint`. A tool that is not installed fails the target, naming it.
- `check-assets` verifies the four completions and the man page match their
  packaged mirrors, and that no source file contains non-ASCII. Editing the
  source copy and forgetting the mirror ships a stale asset in the wheel.
- `smoke` imports the package, builds the full parser, and asserts every
  module in `MODULES` still exposes `register()` and `COMMANDS`, and that
  the commands registered are exactly those in `GROUPS`. pylint scores
  a module 10.00/10 even when an edit has truncated that tail, which breaks
  every command in it; a count to compare against would only go stale.

The Makefile also provides `install`, `uninstall`, `develop`, `reinstall`,
`install-man`, `uninstall-man`, `install-completion` and its four per-shell
targets, `clean`, and `distclean`, all `.PHONY`, with `help` as the default
target printing the paths in effect. Completion destinations default to the
XDG user locations, switch to `$(PREFIX)/share/...` when `PREFIX` is set, and
honour `DESTDIR`. `SHELLS` defaults to `bash zsh fish`; powershell is opt-in.
`uninstall-completion` tests for each exact file rather than removing a
directory, and `uninstall` prefixes pip with `-` so an already-absent package
still cleans up.

CI runs `make check` on Python 3.11 through 3.14, installing ShellCheck and
yamllint from apt, `reuse` and the Python tools from `.[dev]`, Node from
`.nvmrc` with `actions/setup-node`, and markdownlint-cli2 with `npm ci`,
plus jobs that parse all four completions and lint the man page.
`publish.yml` runs the same `make check` before building a release, so it
installs exactly the same tools: a linter added to `make check` is added to
both workflows' install steps, or the next release fails to publish.

**Every workflow declares `permissions`.** Without one, its jobs receive
whatever the repository default grants, which CodeQL flags as
`actions/missing-workflow-permissions` once per job. `contents: read` at the
top of the file is enough for anything that only builds and tests; a job
needing more raises it for itself, as the publish jobs do with
`id-token: write`.

Keep actions on their newest major: GitHub retires the Node runtime beneath
them periodically, so an old major first warns and eventually stops running.
Check `runs.using` in the action's own `action.yml` rather than trusting a
version number, and confirm the inputs still exist before jumping several
majors at once.

`publish.yml` uploads to PyPI through Trusted Publishing (OIDC), so no API
token exists to leak. It builds and verifies in one job, then publishes from a
second that raises only `id-token: write` and names a `pypi` environment,
which is where a deployment protection rule can be attached. Publishing runs
on a published GitHub release; `workflow_dispatch` offers TestPyPI for a
rehearsal, with `skip-existing` so a repeated dry run does not fail.

The release job must confirm the tag matches the packaged version. PyPI
uploads are immutable, so publishing `v1.2.3` from a tree carrying some other
version cannot be undone. Strip a leading `v` before comparing.

## COMMAND PAGES

Beside the roff overview, every command has a detailed page in scdoc source
format: `man/plexdo-COMMAND.1.scd`, one per command, so `playlist-build`
and `playlist-copy` each have one page covering every mode, with a `MODES`
section and each argument marked with the modes that take it, and
`man/plexdo-conventions.7.scd` for what every command shares - the global
options, how users, libraries, playlists, items, and sessions are named,
output formats, path rewriting, pacing, exit status, files, and
environment. Nothing installs them; `MANIFEST.in` ships them in the sdist,
and they sit under `man/`, so `check-assets` holds them to plain ASCII.

They are also the project wiki, one page each. `tools/wiki-pages.sh`
converts them scdoc -> roff -> `pandoc --from man --to gfm`, and `make wiki`
runs it into `build/wiki/`. mandoc cannot do this step: its Markdown output
takes mdoc(7) only, and scdoc writes man(7). The script:
- names the page for the file less its section, so `plexdo-wait.1.scd` is
  the page `plexdo-wait`, and fails if two sources would share a name;
- writes each stage to a file of its own rather than a pipe, since a plain
  POSIX pipe hides a failure upstream and yields a truncated page;
- rewrites `**plexdo-X**(N)` into a link to page `plexdo-X`, and fails when
  a link names a page that was not generated: a dangling reference is a
  build error, not a broken link on the wiki;
- opens each page with a hidden `<!-- Generated from ... -->` comment.

`.github/workflows/wiki.yml` builds the pages in a `contents: read` job, on
every push and pull request touching them, and uploads them as an artifact.
A second job, only for `main` and never for a pull request, raises
`contents: write` - the permission under which `GITHUB_TOKEN` pushes to the
wiki - checks out `REPO.wiki`, and syncs: it deletes a page only when its
**first line** is the generated mark and its source is gone, so a page
written on the wiki by hand is never deleted, then copies the rest in and
commits only when something changed. Check that the wiki repository exists
first with `git ls-remote`: GitHub creates it only once a first page has
been made by hand, and checkout's bare "repository not found" does not say
so. The workflow is in a `wiki` concurrency group, queued rather than
cancelled, since two pushes to the wiki at once would race.

Each command page has, in order: NAME, SYNOPSIS, DESCRIPTION, ARGUMENTS,
OPTIONS, GLOBAL OPTIONS, OPTION INTERACTIONS, OUTPUT, EXIT STATUS, EXAMPLES,
and SEE ALSO. GLOBAL OPTIONS says what **each** global flag does for that
particular command - "no effect" is an answer, and `--dry-run` writing a
file anyway is worth saying. OPTION INTERACTIONS covers every conflict and
dependency, whether argparse enforces it (`-u`/`-a`) or the handler does
(`find-missing -A` with SHOW, `wait --now` without `-r`). Document what the
code does, checked against it, not what a help string implies. Sample tables
are real output from `print_table` with an ASCII console, never hand-drawn.

scdoc accepts several mistakes silently, so follow these rules:
- **Write every flag in prose bold**, `*--flag*`. A line starting with a
  bare `-` is a scdoc error, and wrapping puts flags at line starts.
- **No spaced ` - ` dash in prose.** Wrapped to a line start it silently
  becomes a bullet. The NAME line's `name - summary` is the one exception.
- **Escape a literal `*` as `\*`.** An unclosed one silently eats text.
- **Never start a line with `[`, `|`, or `:`.** scdoc reads it as a table
  row anywhere, not only after a blank line; escape it as `\[`, which
  wrapped SYNOPSIS lines need. A line starting `; ` silently vanishes as a
  comment, and one starting `. ` is a numbered list.
- **A word-initial `_` underlines.** Mid-word underscores are literal.
- Indent with TABs only, and double every backslash, inside literal blocks
  too: a Windows path `\\NAS\media` is written `\\\\NAS\\media`.
- Wrap at 80 columns, counting a TAB as eight.

Validate by compiling every page with scdoc and checking the roff with
`groff -man -ww -z`, and check that every option string of every command
appears bold in its page.
